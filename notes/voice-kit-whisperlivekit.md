## 1. How Voice Kit attaches to Paseo

**Verified — Plugin and process.** The listing points to `swordfeng/paseo-voice-kit` at revision `82023555b87b`. Its manifest declares ID `voice-kit` and Paseo ≥0.15.4. Paseo loads the conventional server entry in a subprocess and the client entry in each connected app. The plugin supervises a separate Rust executable, `voicekit`, on the daemon host. Speech travels over token-authenticated loopback HTTP to its OpenAI-compatible endpoints. ([Listing][vk-list], [manifest][vk-man], [architecture][vk-arch], `docs/plugins.md:3`, `docs/plugins.md:45`)

**Verified — RPCs and native surfaces.** On load the client calls `voicekit.attach`. The server obtains the calling session’s `context.paseo` and uses `paseo.config.patch` to change speech settings. Other typed RPCs cover status, restart, model listing/download/removal, voices, preview, reclaiming a setting and logs. The client contributes a native screen, sidebar footer row, plugin settings screen, workspace slash command `/voicekit`, and Command Center actions for settings, restart and preview. It registers **no composer attachment source**. That SDK feature selects material to submit with a message. Neither microphone audio nor live transcripts use it. ([Client entry][vk-client], [server entry][vk-server], [RPC definitions][vk-rpc], [settings switch][vk-switch], `docs/plugins.md:698`)

**Verified — What it replaces.** When ready, Voice Kit points three independently managed settings at its server as provider `openai`: dictation STT, voice-mode STT and voice-mode TTS. It remembers previous settings, falls back when unavailable, restores on disable/removal, and yields a feature if the user edits it. Listening defaults to Whisper turbo on Mac or a sufficiently fast tested GPU, otherwise Qwen3-ASR on Linux/Windows. **Verified — Who owns the turn.** The daemon sends a completed utterance to `/v1/audio/transcriptions`. Voice Kit preserves Paseo’s live Silero detector, even ensuring the daemon’s local model directory is configured when all three speech settings point elsewhere. ## 2. Paseo voice mode from microphone to reply

**Verified — Source scope.** Checkout HEAD is `2c23cd492`. Below and above, paths beginning `audio/` or `voice/` are under `packages/app/src/`. 3. **Verified — Local and cloud speech.** Local is the default for voice STT, TTS and VAD. A daemon worker runs sherpa-onnx. The voice worker uses offline recognition on commit. The separate periodically decoding recognizer is for dictation. OpenAI STT buffers 24 kHz PCM, writes a WAV and posts it via the transcription API, returning one final. Its default model is `whisper-1`. OpenAI TTS defaults to `tts-1`, `alloy`, PCM. 4. **Verified — Turn-taking and barge-in.** The worker’s Silero state machine defaults to 800 ms of confirmed speech and 1,000 ms of silence to end a turn. Resumed speech cancels a pending end. The selected agent gets `enableVoiceTools` in its caller context. The tool looks up the handler by caller agent ID and passes text and cancellation. Runtime launch supplies the agent-scoped Paseo MCP configuration or the provider’s native Paseo tools. (`session.ts:1248`, `session.ts:2018`, `session.ts:4024`, `voice-config.ts:4`, `voice-config.ts:56`, `voice-types.ts:1`, `voice-permission-policy.ts:5`, `session/voice/voice-session.ts:501`, `session/voice/voice-session.ts:1087`, `agent/agent-manager.ts:5495`, `agent/agent-manager.ts:5573`, `agent/tools/paseo-tools.ts:1313`)
6. **Verified — Audible reply and latency.** The speak handler merges cancellation signals and awaits TTS **and playback**. The TTS manager splits text, prefetches two segments and collects the entire first segment’s audio before sending it as base64 `audio_output`. Latency before first sound therefore includes mic buffering and transit, end-of-speech silence, committed recognition (plus upload for HTTP), the agent’s time to call `speak`, first-segment synthesis, return transit and playback startup. ## 3. Where WhisperLiveKit fits

**Verified — Streaming contract.** Public upstream `496b5f614168` exposes native WebSocket `/asr`. With `--pcm-input` it takes binary mono 16 kHz signed little-endian PCM. In default full mode each JSON update contains the committed lines so far and a replaceable `buffer_transcription`. Empty input drains to `ready_to_stop` and closes the socket. The Deepgram-compatible `/v1/listen` also accepts raw PCM and can emit interim results, immutable ranges and speech events. It supports terminal `CloseStream` and explicitly rejects non-terminal `Finalize`. REST `POST /v1/audio/transcriptions` accepts a whole file and returns text using the server’s selected model. The documented service supplies no TTS. ([API reference][wlk-api], [README][wlk-readme])

**Verified — Speech features and hardware.** Upstream enables voice activity detection and control by default and offers SimulStreaming or LocalAgreement for Whisper. Optional Sortformer (four speaker channels in the default checkpoint) or Diart attributes words to speakers. Whisper covers roughly 100 languages, with explicit or automatic per-session language selection. Other backends have narrower coverage. Optional translation is a separate stage. CPU operation is supported, with CUDA and Apple Silicon MLX acceleration for suitable backends. Costs depend on model, backend and concurrent workers, each of which loads its own weights. The published comparison uses an H100 and audiobook speech. ([README][wlk-readme], [languages][wlk-lang], [backends][wlk-back], [deployment][wlk-deploy], [API reference][wlk-api])

## Recommendation

**Inferred — Estimate.** With a reachable WhisperLiveKit service, budget a few hours for the HTTP comparison. If post-speech recognition accounts for enough of the wait to matter, budget **2–4 engineer-days for a streaming prototype** on one daemon and one client. That includes provider selection, socket rollover, cancellation and timing instrumentation. Test consecutive turns, pauses mid-command and interruptions during playback. Shipping cross-platform service installation and a live transcript UI would be separate work. (`speech/speech-runtime.ts:487`, `speech/speech-provider.ts:34`, [WebSocket contract][wlk-api])

**Inferred — Decision test.** Compare the same spoken commands with built-in sherpa, Voice Kit and WhisperLiveKit on the intended host. Record recognition errors on names and code identifiers, last word to final text, final text to first audible reply, and false cuts or missed interruptions. Keep VAD, agent and TTS fixed. Diarization and a second turn detector offer little for a single person addressing one agent. A streaming adapter earns its cost if it improves the audible exchange on that hardware. These are research estimates and proposed measurements.

**Inferred — If “our WhisperLiveKit” is a fork,** the comparison needs its repository URL and commit, deployed backend/model and hardware, and any changes to partials, turn flushing or endpointing. In particular, reusable per-turn flush would simplify the adapter. The assessment above uses public upstream only.
